# 模型与连续运行

出牌默认使用固定DouZero ResNet社区评测权重，保留WP作为可选后端；三种身份分别加载独立权重，在CPU子进程推理，不训练。对手未知牌只作为合并集合，不分配成两家的隐藏手牌。

## 模型选择与输入

```powershell
uv run ddz-check setup-agent --model resnet
uv run ddz-check setup-agent --model wp
uv run ddz-lab --play-model resnet
uv run ddz-bot-demo --play-model wp
```

设置中的“出牌模型”保存偏好；命令行选择只作用于本次运行。ResNet权重来自`godmoves/perfectdou`提交`eaf0436676c199507fe5420e464daa951a83d704`，存放在数据目录的`models/douzero-resnet`；WP继续使用`models/douzero-wp`。准备命令核对固定文件大小和SHA-256，在隔离目录完成三身份严格加载及预热后发布清单。正式启动只加载本地权重。

ResNet输入为`z_batch=[N,40,54]`和`x_batch=[N,15]`，N是合法动作数量。前者编码候选动作、三家剩牌数、本人手牌、其他两家合并剩余牌、剩余底牌、三家已出牌及最近32次行动。历史倒序排列，前方不足部分填-1，真实“不出”编码为零；剩余底牌按原始底牌减去地主已出牌的多重集合计算。

15维输入沿用上游评测固定兼容常量：叫抢矩阵`[[1,0.5,1],[1,1,1],[1,1,-4],[1,1,1]]`按行展开，再接`[1,1,1]`。这些值不代表本局真实叫抢或倍数观察，也不用于更改现有Net2叫抢和不加倍策略。编码不访问模拟器各家的隐藏手牌。

候选按256个分片评分，取全局最高值，平分保持原候选顺序。返回原始网络评分，不乘评测脚本用于缩放的8倍，也不转换成胜率；不同后端的评分不直接比较。单次推理仍限时2秒。动作账本分别记录`resnet`、`wp`和`rules`，旧记录缺少策略字段时按WP解释。本次接入验证合法动作、闭环和生命周期，没有开展棋力对战评测，也不据此声明胜率提高。

叫抢使用固定Net2模型，只输入自己的17张牌。新配置的首叫、首次抢和回抢阈值统一为0.5，可在“设置 → 连续游戏 → 叫抢阈值”修改，保存后下一次任务的三个阶段共用该值。评分严格高于阈值才叫抢，调低阈值更积极；输出为未经本游戏校准的原始评分，不是胜率。旧配置仍保留原分阶段阈值，只有显式填写统一值并保存后才统一，详见[配置说明](configuration.md)。始终不加倍。

## 日常运行

软件打开后自动后台加载所选本地模型，顶栏显示模型名称及加载中、已就绪或失败。失败原因直接展示，可重试，不自动下载、不自动回退WP。空闲时切换会撤销旧建议，串行关闭旧进程再加载新模型，忽略旧任务迟到的成功结果。唯一授权手机自动只读预览，多台手机在设置中选择。加载模型和显示画面均不自动操作手机。

模型就绪后点击“开始连续游戏”，自动准备录像并负责大厅匹配、叫抢、不加倍、出牌和下一局。正在截图预览时先暂停预览并等待当前任务结束，无需重复点击；等待期间可用“停止任务”取消。启动途中取消也会回收迟到的录像资源，不会自动重启。

任务面板集中显示阶段、有效完成局数、异常跳过局数、恢复次数、用时、身份、剩牌和当前动作。异常时显示“自动恢复中”或“等待条件恢复”，无需手动点恢复；下次检查倒计时直接展示。停止后立即撤销后续输入及重试，后台保存录像和报告；完成后恢复只读预览，本地模型在空闲执行进程内驻留。

## 无人值守与恢复边界

日常命令行和桌面连续任务使用父进程看护器及独立执行进程。模型、识别、单局机器人和录像协调均在可回收的执行进程内；录像继续由独立采集子进程写盘。界面只读取本地快照并刷新输入租约，不等待识别锁、USB 或旧进程收尾。显式只录像及正式验收入口仍保留完整录制路径。

单局历史缺失、矛盾或结算校验不完整时，立即停止本局机器人输入，保留异常窗口，继续观察。明确结算页的可用续局按钮取得两帧稳定证据后，记录跳过并继续下一局；异常局不计为有效完成。局中异常等待游戏自身自然结束，不启动托管、不关闭或重启手机游戏。下一局仍需验证完整开局，不能靠进程重建中途接管旧局。

工作进程退出或卡死后，保留本次任务账本，自动关闭并重建本次拥有的软件进程。恢复等待依次为2、5、10、30、60秒，之后每60秒重试；完成一局有效局后重置退避。启动总期限90秒，旧执行进程收尾最多45秒，超期回收专属进程树，不终止公共ADB服务。重试次数和任务总时间不设上限。

显式`--continuous`启动已经提供本次任务授权，初始模型暂未就绪或加载失败时也会进入自动恢复，无需点击“重试加载”。普通桌面主按钮仍在模型就绪后启用，空闲预热和只读预览本身不授权游戏操作。

设备离线、游戏不在前台、登录或系统提示阻塞时，保存资料后每60秒进行一次只读探测；条件恢复后自动续跑，不重复创建录像会话。只连接原设备，不切换手机、不操作登录或授权、不下载模型、不绕过游戏系统限制。若外部条件长期不恢复，任务会一直等待，不能保证无条件完成。桌面软件主动停止或关闭后不续跑，主程序崩溃及开机自动恢复不在此功能范围内。

每次有效完成先写入父任务账本并确认成功，再允许开下一局。一个任务可以关联多个录像与执行会话；完成和跳过按稳定牌局标识幂等登记，恢复不会清零进度。旧页面命令结果未知时保留原始记录，不重发；替代执行进程只有观察到明确离开原页面后才能归档未知命令。用户停止立即使租约失效，迟到回调不能重新授权。

报告中`target_reached`表示有效局数达到目标，`passed`继续表示严格连续运行和证据检查结果。恢复后补足局数不会把历史故障或缺失录像改成严格验收通过。旧单会话账本继续按原格式读取，不改写历史数据。

日常窗口移除单步和单局模式。底层仅建议、单步和单局自动控制仍供隔离模拟与自检使用，不通过隐藏控件保留旧界面。

始终沿用当前页面，不再选择或限制玩法名称和场次等级。洗牌、不洗牌、经典、未知名称或没有玩法文字的大厅，只要右下角“开始匹配”按钮通过文字置信度、位置及底色校验，就可开始；也可在已确认的结算页通过“继续游戏”“继续对局”或“再来一局”等已识别续局按钮开始下一局。按钮需要两帧稳定证据，只提交一次。任务从大厅匹配或结算续局建立完整开局，不直接接管历史缺失的牌局。

在已有牌局中启动时，任务保持运行并显示“等待当前牌局结束后开始下一局”，继续只读录制、识别及健康监控，不出牌、叫抢或加倍。到达结算页后优先点击经双帧确认的续局按钮；提交后必须收到大厅、匹配或新局页面的推进反馈，才授权下一局流程。没有可用续局按钮时，可点击明确的“返回大厅”并等待大厅入口确认；不会仅凭“退出”或“返回”猜测去向。战绩展示的“继续”只关闭展示，随后仍须确认正式结算页的续局按钮。没有可靠按钮时保持等待并提示手动返回。启动前的旧局不计入完成数，也不算程序故障；下一局仍须完成原有开局和历史完整性校验。等待不受任务总时长限制，停止按钮始终可用；设备、识别和页面阶段的异常保护继续生效。

入口不限玩法，出牌仍按现有单副54张牌、地主20张和农民各17张的标准规则及模型工作；不新增癞子、多副牌或特殊牌型，也不据此宣称不洗牌模式的胜率提高。沿用当前可识别的按钮布局。

```powershell
uv run --extra vision ddz-lab --continuous --continuous-policy balanced --bidding model
```

默认最多5局，不限制任务总时长；设置中的“最多局数”和`--max-games`接受任意正整数，不设局数上限，0不表示无限运行。目标局数完成后正常收尾，不再匹配下一局；面板只显示已用时间。旧`--time-limit`参数隐藏但继续接收，其值被忽略，启动时提示一次弃用；心跳、卡住检测、初始化预热和匹配等阶段超时不受影响。旧`--flow-room`参数继续接受任意字符串，但不再限制场次，也不保存该参数。

游戏提示“已为您切换至／到……”时，只要同帧文字给出唯一明确目标，且存在通过校验的普通“确定”按钮，就可自动确认任意场次或玩法。仅说明游戏币不足、已切换场次的普通提示也可继续；目标缺失或冲突、确认按钮无效、充值、购买、支付、健康系统等提示进入自动等待，不发送未知点击。

本次新行为在重启程序后生效，新任务自行确认大厅或结算续局入口，不从历史任务恢复自动授权。无法识别的页面持续五秒后进入自动等待；牌局矛盾、未知提交等校验继续阻止本局不可信输入。

## 推断优先与单局隔离

新会话采用`evidence_policy_version=2`。严格、推断、平衡模式均接受可独立复核的确定性推断；规则接管仍只属于平衡模式，并单独计为降级。严格通过要求完整合法历史、全部本人提交已确认、证明有效以及原有录像和采集条件满足。历史会话未记录该版本时保持原评测口径，不追改旧成绩。

短暂缺失先收集同一设备、视频流和牌局的两个原始帧，间隔至少100毫秒。手牌及计数守恒和唯一轮转可以证明不出；本人精确手牌差分可以证明实际出牌；明确零剩牌和末手证据可以确认已知剩余手牌打完。开局本人17至20张的差分可证明三张底牌，唯一20张计数可辅助确认地主。对手漏识别的单个动作只在公开牌张、张数、牌型及轮转只剩唯一合法答案时补全；发现第二个候选或搜索超过4096个候选就保留未知。

证明保存在独立运行事件中，记录类型、前置状态指纹、原始帧及时间范围。独立评测从原始观察重新求解，不直接相信确认标记。模型建议、发送意图、ADB成功返回均不是出牌事实；本人动作还须与账本中的单次真实提交匹配。原始观察和视觉识别指标不被推断覆盖，真实采集缺口、多解或有效证据冲突继续阻止输入。

完整开局和地主身份已确认后，首轮稳定牌面与剩牌减少也可以确认出牌阶段，不必等到自己的按钮出现。证据跨越至少100毫秒，牌型、差分和轮转必须合法；自己领出还核对手牌差分。源时间与原始观察保留，已经确认的阶段和动作不因短暂准备动画或遮挡回退。流程识别只接受相同源帧的已确认阶段提示，明确结算和阻断页面仍优先处理。

平衡模式在历史不完整但当前回合明确时可使用规则策略，棋力可能下降，并单独记录。按钮和选牌不根据猜测点击；手牌不确定、轮转矛盾、真实缺口或未知提交时停止本局输入；系统阻断时等待外部条件恢复。

每次选牌后重新定位，提交前两帧核对选中多重集合。普通确认窗口3秒，炸弹／王炸原有5秒窗口保留；有持续有效画面时，所有模式均可只读取证至提交后最多8秒，期间不重复点击。命令返回未知时也保留单次提交并等待确定证据，不能按“未发送”重试。底层明确拒绝的过期点击才允许撤销提交占位，取得新帧后重新核对。实际点击仍要求画面年龄不超过1秒。

页面意图先写入父账本，确认后重新检查同一机会的最新按钮，实际发送帧和时间另行记录。续局即使漏识别页面文字，也可通过提交后的稳定新牌局证据确认。原始视频持续到达但流程结果过期时最多等待8秒；真正断流、心跳失效、场景阻断及停止请求仍立即撤销后续输入。

“停止任务”会锁住后续授权，已经发出的单次命令记为在途，不能撤回。执行会话异常后不重新授权该故障会话，而由看护器在同一任务下建立替代会话继续；停止请求会取消整个任务的恢复。正常局和主动中止局清理临时录像，异常媒体按本次任务配额轮转，详细规则见[记录与回放](recording-and-replay.md)。输入授权不跨桌面程序重启或跨新任务恢复。

```powershell
uv run ddz-check simulate-continuous --runs 6 --policy balanced --bidding model --require-pass
uv run ddz-check evaluate-run .\data\runs\示例任务 --require-pass
```

模拟与真机分别标记。30局任务必须实际完成30局才能通过，不累计失败批次。当前实测限制见[验证状态](validation.md)。
