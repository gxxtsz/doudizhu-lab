# 安装与启动

目前支持Windows、Python 3.11和USB安卓真机；其他系统尚未完成设备与窗口验收。首次运行建议先使用模拟器演示，不连接手机。

## 环境

安装uv和Android Platform Tools。ADB放入PATH，或在“设置 → 设备连接”中选择其完整路径；也可设置`ADB_PATH`。程序不捆绑ADB，不修改手机权限。

```powershell
uv sync --frozen
uv run ddz-lab --version
uv run ddz-lab
```

连续流程和可选手牌OCR需要额外依赖：

```powershell
uv sync --frozen --extra vision
uv run ddz-check setup-video
uv run ddz-check setup-agent
uv run ddz-check setup-bidding
uv run --extra vision ddz-check setup-vision
```

这些准备命令会显式联网下载固定版本并检查SHA-256；正式运行不隐式下载。`setup-agent`默认准备三种身份的ResNet副本（约42.6 MB），`setup-agent --model wp`保留WP准备入口。`setup-bidding`准备叫抢模型，`setup-vision`只准备三份PP-OCRv5模型。不训练模型。

网络较慢时，可以在本机安装命令中选择可信镜像；请保留PyTorch CPU专用索引和锁文件校验。项目默认索引仍为官方PyPI，不提交个人镜像设置。

## 不连接手机的演示

模型准备完成后：

```powershell
uv run ddz-bot-demo
```

演示使用模拟设备，不能证明真实牌面识别或实际操作成功率。`ddz-device`兼容旧桌面启动命令；`python -m doudizhu_lab`也可启动桌面程序。

## 连接手机

1. 打开USB调试，连接可传输数据的USB线，在手机上授权电脑。
2. 软件自动加载所选本地模型，默认ResNet；可在“设置 → 连续游戏 → 出牌模型”选择WP。唯一授权设备自动显示只读画面。多台设备时在设置中选择目标并保存；未授权时先在手机确认，再刷新设备。
3. 确认已有适用于当前设备与游戏布局的[标定配置](calibration.md)。公开源码不含游戏图片或预配置的可执行按钮，日常界面不承担首次标定。
4. 在设置中确认连续策略、叫抢策略与最多局数。选择“模型自动叫抢”后可编辑统一叫抢阈值，新配置默认0.5，首叫、首次抢和回抢共用；阈值越低越积极，保存后下一次任务生效。局数须为正整数，不设上限，任务不限制总时长。手机停在当前大厅或结算页，模型就绪后点击“开始连续游戏”。大厅通过“开始匹配”进入新局，结算页通过“继续游戏”等续局按钮进入下一局；启动前已结束的旧局不计入完成数。不限制洗牌、不洗牌或场次等级；按钮仍须通过文字、位置、底色及两帧稳定校验，提交后等待页面反馈。
5. 右侧显示阶段、局数、用时和当前局面。暂停原因直接显示，条件修复后可明确恢复；真实历史缺口仍拒绝恢复。
6. “停止并保存”立即撤销后续操作并后台保存录像，结束后恢复只读预览。“查看本次回放”或顶部“录像回放”可查看记录；运行日志默认折叠。

主界面移除坐标点击、画面控制、截图导入导出、标定、单步和正式验收入口。截图诊断与验收仍可通过既有命令行执行。模型缺失或校验失败时显示中文原因与重试按钮，不隐式下载，也不自动开始游戏。

小米系统若返回`INJECT_EVENTS`权限错误，检查手机上的“USB调试（安全设置）”。程序会显示原始诊断，不自动打开权限、不修改系统设置。

## 常见问题

- **模型未就绪**：检查对应准备命令及本机清单；缺失、损坏或不兼容都会阻止执行，不使用随机权重。
- **整局记录不可用**：检查scrcpy组件、USB连接、前台状态和可用空间。视频失败不会静默宣称完整录制。
- **无法确认牌面**：检查布局、模板覆盖、遮挡及动画。未知区域不等于没有牌。
- **结算页能否开始连续游戏**：可以。在结算页点击工作台的“开始连续游戏”后，程序自动确认并点击游戏内的“继续游戏”等续局按钮，从下一局开始计数。任务运行时开始按钮变灰是正常状态，可随时点击“停止任务”。已有牌局尚未结束时只读等待，不中途接管。
- **未知页面持续五秒**：当前版本已取消玩法名称限制；确认已重启并从大厅或结算页新建任务，检查“开始匹配”或续局按钮是否可用且处于现有布局位置。真正不能识别的页面仍暂停，不直接接管历史缺失的牌局。
- **健康系统或账户提示**：任务停止并保留现场；不使用旧牌桌状态继续点击。

入口不限玩法，模型和合法动作仍按单副54张牌标准规则工作，不新增癞子、多副牌或特殊牌型。游戏币不足后已明确切场且仅需普通确认的提示可继续，充值或购买提示仍暂停。

数据目录、覆盖顺序及默认行为见[配置说明](configuration.md)；当前实际完成程度见[验证状态](validation.md)。
