# 已有区域、模板与操作标定

日常界面只保留运行、回放与必要设置，已移除标定、模板采集和单步验证入口；本次不提供维护窗口或首次标定向导。已有本机配置与模板继续使用，不会被新界面重置。首次适配新设备需要手工维护配置与模板，或另行开发专用工具。

模板依赖游戏布局和尺寸。默认区域是2400×1080经典牌桌的起点，不是通用适配保证。仓库不附游戏画面或预配置的可执行按钮。

## 手工维护约定

退出软件并备份数据目录后，再修改第四版`settings.json`及模板文件，避免与软件保存配置互相覆盖。配置结构见[配置说明](configuration.md)与[示例配置](../examples/settings.example.json)。

- `profile.regions`保存手牌、底牌、左右出牌与自己出牌的归一化区域；`glyph_heights`保存对应牌点高度，依据`base_width`与`base_height`缩放。
- `templates`内手牌、底牌和桌面小牌分组保持原规则；三家已出牌共享桌面模板。`SJ`为小王、`BJ`为大王。已有PNG及配套来源JSON应一起保留。
- `indicator_regions`与`markers`保存地主、行动提示、剩牌数、阶段和不出字样；“不抢”属于叫抢阶段，不能当作不出。
- `seat_order`保存已核实的真实座位轮转；`bot_controls`保存常态牌顶、选中上移量、容差及出牌／不出按钮区域。未完成有效标定时不得将`verified`改为真。
- 模板裁剪避免头像、昵称、聊天泡和顶部记牌器；使用不同牌局来源验证，不将机器预测当作人工真值。

截图与离线识别仍可通过命令行执行，不发送手机输入：

```powershell
uv run ddz-check capture --serial 你的手机序列号
uv run ddz-check recognize .\截图.png
```

模板不全、遮挡或匹配不明确时拒绝识别，匹配分数不是概率或胜率。可选手牌OCR只替换字形分类，仍依赖候选分割和区域配置；底牌与桌面模板仍然必要。

任务期间设置只读。离线调整后重启软件并创建新会话，防止同局混用不同配置；历史会话快照保持原样。
